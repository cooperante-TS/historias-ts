Manual de gestión de Historias TS

Para el trabajo normal no necesitas tocar código. Los hitos se gestionan desde la hoja institucional y la web se actualiza automáticamente.

Publicar un nuevo hito

  1. Abre la hoja institucional de gestión.
  2. Entra en la pestaña del país correspondiente.
  3. Crea una fila nueva con un ID que no exista ya.
  4. Completa fecha, tipo, título, resumen, imagen y fuente.
  5. Trabaja primero como BORRADOR, después REVISAR y finalmente PUBLICAR.
  6. Abre historias-ts.pages.dev y comprueba el resultado.
Importante: la hoja privada de gestión no debe hacerse pública. El feed técnico puede ser públicamente legible para que funcione la web, pero nunca públicamente editable.

Si el cambio no aparece

  1. Comprueba que el estado sea PUBLICAR.
  2. Comprueba que estás editando la hoja institucional correcta.
  3. Recarga la web con Ctrl+F5.
  4. Si sólo falla una imagen, sustituye su URL por una imagen estable de TS.
  5. Si sigue sin aparecer, pide ayuda antes de tocar GitHub o Cloudflare.

Pedir un cambio de diseño a ChatGPT/Codex

Usa el repositorio institucional cooperante-TS/historias-ts y pega:

Lee README.md, AGENTS.md y docs/ antes de modificar nada. Quiero este cambio: [DESCRIBIR]. Mantén los seis países, el modo embed=1, el snapshot local y la conexión con el feed institucional. Haz el cambio de forma reversible y comprueba escritorio y móvil.

Qué no debes tocar

  • No edites el feed público a mano.
  • No hagas pública la hoja privada.
  • No concedas edición pública al feed.
  • No sustituyas las hojas institucionales por hojas personales.
  • No cambies Cloudflare para publicar un hito normal.

Si una modificación técnica rompe la web

Restaura el último commit estable del repositorio institucional. Cloudflare Pages volverá a desplegar automáticamente esa versión. No edites producción manualmente.
